# BankManager - instructions for every Claude instance

Three people are building this repo at the same time, each with their own Claude,
each on ONE partition. Follow these rules exactly. Full detail: `plan.txt`
(read sections 13, 14 and **15** before writing any code).

## 1. Find out which partition you are
Your person will say P1, P2 or P3. If they have not, ASK. Do not guess.

| Partition | Name | You may edit ONLY |
|-----------|------|-------------------|
| **P1** | Data & MCP server | `data/` `mcp_server/` `fixtures/real/` `docs/p1/` |
| **P2** | Calc, audit & eval | `calc/` `audit/` `backtest/` `predictions/` `docs/p2/` |
| **P3** | Agents, orchestrator & web | `agents/` `prompts/` `orchestrator/` `web/` `tests/e2e/` `docs/p3/` |

Everything else is READ-ONLY for you: `schema/`, `fixtures/mock/`,
`tests/contracts/`, `scripts/`, `Makefile`, `.gitignore`, `.env.example`,
`README.md`, `plan.txt`, other partitions' folders. The one exception: you may
ADD a new file in `docs/requests/` (never edit an existing one).

## 2. Session start
1. `git pull --rebase origin main`
2. `make install-deps && make install-hooks` (once per clone)
3. Read `plan.txt` 15.x, your partition brief (15.14), and `docs/p*/STATUS.md`.
4. New files in `docs/requests/` addressed to you? Read and act on them.
5. Work on your own branch: `p1-data`, `p2-calc` or `p3-agents`.

## 3. Rules that prevent conflicts
- Call other partitions ONLY through their `api.py` (`data/api.py`, `calc/api.py`,
  `audit/api.py`, `orchestrator/api.py`). Never import their private modules.
- Do NOT change any `api.py` signature or any file in `schema/`. Need a change?
  Write `docs/requests/YYYY-MM-DD-pX-to-pY-<slug>.md` and keep working on the mock.
- Bug in another partition? Request file with a minimal repro. Never patch their code.
- Conventions (plan.txt 15.6): fractions not percents (0.25 = 25%), full USD,
  ISO dates, missing = `{"value": null, "status": "unavailable"}` (never 0), every
  financial number is a value object with `type` and `source_id`/`derived_from`.
- `BM_MODE=mock` (default) and `BM_LLM=mock` let you work with no keys and no
  waiting: every `api.py` returns the fictional ACME fixtures until its owner
  replaces the internals. Keep mock mode working when you go live.
- Never commit secrets. Real keys live only in your local, gitignored `.env`.

## 4. Before EVERY commit
```
git status                                   # stage explicit paths only:
git add <your paths>                         # NEVER `git add -A` or `git add .`
make check-contracts                         # must pass
make check-ownership P=p1|p2|p3              # must pass
git commit -m "[p1] short message"           # prefix [p1] [p2] [p3] [step0]
```
Before merging to main: `git fetch && git rebase origin/main`, re-run both checks.
Never force-push `main`. Update `docs/pN/STATUS.md` whenever something moves from
mock to real.

## 5. Ground truth files
- Contracts: `schema/*.json` (authority) mirrored in `plan.txt` 15.7.
- Sample data: `fixtures/mock/` (fictional company ACME, generated by
  `scripts/gen_mock_fixtures.py`).
- ACME is FICTIONAL. Never present mock numbers as real market data.
