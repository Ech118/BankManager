## Layout rules

These come from the original plan review and are not stylistic preferences.

1. **Verdict card first.** The original design put the verdict after fifteen
   sections, which buried the answer the reader came for.
2. **The case against, immediately after the card.** The red team's summary and
   the synthesizer's response sit above the supporting detail, not below it.
3. **Sections expandable**, collapsed by default.
4. **One lane per agent** during a run, fed by the SSE stream. This is also the
   clearest demo visual: a viewer can see two agents running at once.
5. **Colour-code every number** by `type`: `fact`, `estimate`, `assumption`. A
   discount rate and a reported revenue must not look alike.
6. **`unavailable` renders as "unavailable"**, never as 0 or a blank cell.
7. **Unverified claims render with a visible marker**, never hidden. A reader
   must be able to tell a checked report from an unchecked one.
8. **Data-quality banner** whenever `data_quality.overall` is not `ok`.
9. **The disclaimer appears on every page.** There is a test for it.

## Layout

```
app/            routes: / (analyze a ticker), /demo (the ACME fixture, no backend)
components/     Report, VerdictCardView, RedTeamView, SectionList, AgentLanes, Analyzer,
                DataQualityBanner, NumberBadge, Disclaimer, SiteShell (every page renders inside it)
lib/types.ts    TypeScript view of schema/*.json (hand-maintained; tests/api.test.ts checks it against the fixture)
lib/format.ts   formatValue: mirrors orchestrator/report/generator.py, character for character
lib/markdown.tsx  a small SAFE renderer for report bodies (builds React nodes, never raw HTML)
lib/api.ts      orchestrator client: mock loader, POST /api/analyze, verdict fetch, SSE
scripts/sync-mock.mjs   copies fixtures/mock/verdict.json into public/mock/ (gitignored) on dev/build
tests/          vitest + Testing Library
```

## Why hand-written types today

`schema/*.json` is generated from the pydantic contracts. `lib/types.ts` mirrors the parts the UI reads by hand;
`tests/api.test.ts` fails if the real fixture stops matching. TODO(Step 3): generate them from `schema/*.json`.

## The markdown contract with the Python generator

Report bodies are generated by `orchestrator/report/generator.py`. The UI turns three tokens into badges:
`(40.0% · fact)` (coloured by type), `**[UNVERIFIED]**` and `_[unchecked]_`. The golden file
`tests/fixtures/section_bodies.md` is the generator's real output; a Python test
(`orchestrator/tests/test_report.py::test_ui_golden_sample_matches_the_generator`) fails if the format drifts, and the
UI tests parse the same file.

## Untrusted text

Report text originates from filings and models. `lib/markdown.tsx` never uses `dangerouslySetInnerHTML`; markup in the
text is shown as text (there is a test that plants `<script>` and `<img onerror>`).

```bash
npm install
npm run dev        # http://localhost:3000; /demo works with no backend; /?ticker=ACME auto-runs
npm run typecheck && npm test && npm run build
# live demo (from the repo root), lanes visible:
#   uvicorn tests.e2e.support.dev_app:app --port 8000     # real Coordinator over the MCP test double
#   cd web && npm run dev
```

`NEXT_PUBLIC_API_BASE` overrides the API URL (default `http://localhost:8000`).
